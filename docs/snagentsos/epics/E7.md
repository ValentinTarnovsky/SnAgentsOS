# E7 - Git

## Objetivo y problema

Hoy SnAgentsOS no sabe nada de git. `Workspace.cwd` existe (`src/shared/types.ts`), pero ningun archivo de `src/` lee la rama, el estado sucio o el diff: no hay `src/main/git`, ni `execFile('git')`, ni nada de porcelain. Cuando Claude o Codex terminan, hay que abrir VS Code o correr `git status` en cada repo para ver que cambio. Para pedir correcciones hay que escribir a mano "en X.java linea 40...". Dos agentes en el mismo workspace editan el mismo checkout y se pisan. Arrastrar una captura sobre una consola la pega como texto entre comillas con `pty.write`, asi que el agente no la adjunta como imagen. Esta epica agrega cinco cosas:
- conciencia de git de solo lectura (chip y panel Changes);
- un circuito de revision (notas que se mandan al agente);
- adjuntar archivos soltandolos sobre un pane;
- worktrees aislados por consola;
- la API de backend que consume la pantalla Changes mobile de E3.

## Alcance (in) / Fuera de alcance (out)

**In**
- Soltar archivos o imagenes sobre un pane. Si el pane es de agente, el path se pega con `term.paste` en "formato agente", asi Claude y Codex muestran `[Image #1]`. Si es un shell, se pega con un formato seguro. Tambien se pueden arrastrar filas desde el panel Changes, con validacion del payload.
- Un `GitService` en main. Para el chip corre `git status --porcelain=v2 --branch -z` + `git diff HEAD -z --numstat -M` + un conteo de lineas de los untracked con cache. Para el panel corre los numstat por area. El refresco combina watcher del gitdir, foco, transiciones de estado del agente, poll del workspace activo y queries remotas.
- Chip de git en el header del workspace, en la sidebar y en el snapshot mobile.
- Panel Changes de solo lectura: Conflictos / Staged / Unstaged / Untracked, diff unificado, F7 / Shift+F7 para moverse entre hunks y menu contextual por fila.
- Notas de revision sobre lineas del diff, persistidas en main y mandadas a una consola en un solo lote. Formato `File:` / `Line:` o `Lines:` / `User comment: "..."`. Solo se mandan a consolas con bracketed paste y el Enter es opcional (apagado por defecto).
- API remota `gitReq`/`gitRes` (cambios y diff paginados, frames de 48KB o menos) + ctl `sendReviewNotes` con notas inline, para que E3 arme la pantalla Changes mobile.
- Worktree aislado por consola: `git worktree add --no-track -b sn/<slug>` con raiz fuera del repo, copia de `.env`, junction opcional de `node_modules`, chip de rama en el pane y dialogo Conservar/Borrar al cerrar. Main lleva un manifiesto `worktrees.json` como fuente de verdad y hay gestion de worktrees huerfanos.
- "Carrera" por etapas (P2, ultimo bloque de v3.0): chips de destino y "Enviar con Enter" en Prompt global, spawn de N agentes en N worktrees y una barra para comparar. Sin auto-merge.

**Out**
- Stage, unstage, discard, commit, push, pull, fetch y resolver conflictos desde la UI. Los agentes ya hacen eso desde su consola.
- Paginas de PR, checks, GitHub/GitLab/Jira/Linear, Monaco, diff combinado o side-by-side, diffs de imagenes, submodulos, ruteo WSL/SSH de git. (Enmienda app 2.2.0: el editor de archivos llega en [E9](E9.md), con CodeMirror 6 y sin Monaco.)
- Fetch automatico. Ahead/behind se calcula contra el ultimo fetch que hizo el usuario.
- Auto-merge en la carrera y titulo de pane generado por LLM.
- La UI mobile de la pantalla Changes. Es de E3; E7 solo entrega datos y endpoints.
- Implementar la confirmacion de cierre por pane para `confirmCloseRunning` (ver Riesgos).

## Historias de usuario

- Como usuario quiero soltar una captura sobre la consola de Claude para que la adjunte como imagen sin escribir el path.
- Como usuario quiero ver en cada workspace `main +142 -37 5 archivos` para saber que repos tienen trabajo sin commitear antes de un release.
- Como usuario quiero abrir el diff de lo que hizo el agente sin salir de la app para revisarlo apenas dice "listo".
- Como usuario quiero marcar lineas del diff con comentarios y mandarlos juntos al agente para que corrija todo en una pasada.
- Como usuario quiero revisar y anotar el diff desde el celular (E3), aunque el desktop este minimizado en la bandeja, para cerrar el circuito desde el sillon.
- Como usuario quiero lanzar una consola de agente en su propio worktree para que dos agentes no se pisen en el mismo repo.
- Como usuario quiero que al cerrar esa consola me pregunten si conservo o borro el worktree, con aviso si hay trabajo sin commitear, y que nunca se borre una rama que no creo la app.
- Como usuario quiero mandar la misma tarea a Claude y Codex en worktrees separados y comparar los resultados.

## Requisitos funcionales

Definiciones que usan varios FR:
- **Pane de agente**: `pane.type in {'claude','codex'}`, o un pane cuyo ultimo `PaneStatusEvt` trae `provider`, y que ademas tiene `term.modes.bracketedPasteMode === true`.
- **Pane con pegado seguro**: cualquier pane con `bracketedPasteMode === true`.
- **Pane plano**: `bracketedPasteMode === false`.

```ts
// remote-protocol.ts importa: import type { GitArea, GitFileEntry, GitDiffHunk } from './git-types'
// cliente -> servidor (v3.0)
| { v: number; type: 'gitReq'; id: string; workspaceId: string; op: 'status' | 'diff'; path?: string; staged?: boolean; page?: number }
// servidor -> cliente (v3.0), cada frame <= 48KB
| { v: number; type: 'gitRes'; id: string; ok: boolean; data: RemoteGitChanges | RemoteGitDiffPage | RemoteGitError; page: number; done: boolean }
export interface RemoteGitError {
  error: 'not_found' | 'not_repo' | 'git_missing' | 'git_old' | 'unsafe_repo' | 'too_large' | 'rate' | 'timeout' | 'git_error'
}
export interface RemoteGitChanges {
  summary: NonNullable<RemoteWorkspaceInfo['git']> & { approx: boolean; conflicts: number; op: 'merge' | 'rebase' | 'cherry-pick' | null }
  files: GitFileEntry[]; total: number; truncated: boolean
}
export interface RemoteGitDiffPage {
  path: string; oldPath?: string; area: GitArea; diffRev: string; binary: boolean
  tooLarge?: { lines: number }; hunks: GitDiffHunk[]
}
// RemoteWorkspaceInfo (v2.2): git?: { branch: string; ahead: number; behind: number; added: number; removed: number; files: number }
// RemoteCtlAction agrega (v3.0):
| { kind: 'sendReviewNotes'; workspaceId: string; paneId: string; notes: Array<{ file: string; lines: string; comment: string }>; enter: boolean }
```

**Zod** (`remote-protocol-schemas.ts`): `id` de hasta 64 caracteres; `path` de hasta 1024; `page` entero de 0 a 999; `notes` de 1 a 50; `file` relativo, de hasta 1024, sin `..` ni caracteres de control; `lines` con `^(\d{1,8}(-\d{1,8})?)?$`; `comment` de 1 a 4000. El frame entero del ctl queda acotado por `MAX_PAYLOAD` (64KB), asi que E3 parte en varios ctl un lote que no entre.

**Rutas**: el `cwd` y el `repoRoot` nunca viajan al celu. `GitService` resuelve `workspaceId` -> target `ws:<workspaceId>` con su mapa de targets; un `workspaceId` sin target da `not_found`. `gitReq` no lleva `paneId`, asi que los worktrees de pane no se consultan desde el celu (ver Riesgos).

**Correccion a la sintesis**: el `maxPayload` de 64KB (`RemoteServer.ts:23`, `MAX_PAYLOAD`) solo limita los frames entrantes (celu -> desktop). Los salientes los acota la backpressure de `SessionManager`: `BACKPRESSURE_DROP` de 512KB descarta `out` y `BACKPRESSURE_KILL` de 4MB mata el socket (lineas 39-43). Por eso las respuestas grandes (lista y diff) se trocean en frames `gitRes` de 48KB o menos, como fija Contratos compartidos: asi no empujan `bufferedAmount` hacia el corte que descarta el output de los panes suscritos. Los 64KB si acotan lo que manda el celu, y de ahi el tope de 4000 caracteres por comentario y el troceo de lotes de notas.

**Version**: `PROTOCOL_VERSION` sigue en 1. `SessionManager.ts` (L206) rechaza cualquier otro `v` con err `'version'`, y todas las adiciones son aditivas: el cliente ignora tipos desconocidos porque el switch de `client.ts` no tiene default. El cliente mobile lo sirve el mismo desktop, asi que los dos lados son del mismo build. Una pagina vieja cacheada se resuelve con el aviso "Recargar" por `appVersion` del epic mobile (M2).

```ts
worktree?: {
  repoRoot: string; path: string
  branch: string                      // 'sn/<slug>'
  base: string                        // sha del commit base
}
// baseRef, linkedPaths y createdAt viven solo en el manifiesto worktrees.json (main)
// schema.ts -> paneSchema: worktree: paneWorktreeSchema.optional()
// OJO: zod z.object() descarta las claves desconocidas, asi que sin esto el campo se pierde al recargar la config.

export interface WorktreeCreateReq { repoCwd: string; slug: string; copyEnv: boolean; linkNodeModules: boolean }
export type WorktreeCreateRes =
  | { ok: true; worktree: NonNullable<Pane['worktree']> }
  | { ok: false; error: 'not_repo' | 'unborn' | 'branch_exists' | 'path_exists' | 'bad_slug' | 'root_inside_repo' | 'timeout' | 'git_error'; detail?: string }
export interface WorktreeInspectRes { exists: boolean; dirtyFiles: number; commitsAhead: number; mergedIntoHead: boolean }
export interface WorktreeRemoveReq { path: string; paneId?: string; deleteBranch: boolean }   // main completa el resto desde el manifiesto
export type WorktreeRemoveRes = { ok: true } | { ok: false; error: 'not_managed' | 'unlink_failed' | 'busy' | 'git_error'; detail?: string }
export interface WorktreeListRes { entries: Array<{ path: string; branch: string; repoName: string; dirty: boolean | null; managed: boolean }> }
```

**Validacion en main** (no se confia en el renderer):
- `create`: slug con `^[a-z0-9-]{1,40}$` + `check-ref-format`; `repoCwd` resuelto con `rev-parse --show-toplevel`; root fuera del repo; `rev-parse --verify HEAD` OK (si no, `unborn`).
- `remove`: `path` normalizado (sin distinguir mayusculas) tiene que estar dentro del root de worktrees (`settings.worktreesRoot` o `dataDir()/worktrees`), existir en el manifiesto y figurar en `git -C <repoRoot> worktree list --porcelain`. La rama tiene que empezar con `sn/` y coincidir con la del worktree en ese listado. Cada `linkedPath` del manifiesto es hijo directo del worktree y `lstat().isSymbolicLink()` da true. Si algo no cuadra: `not_managed`. Para los huerfanos descubiertos por escaneo que no estan en el manifiesto, `listManaged` los agrega al manifiesto despues de validarlos con `worktree list` (ruta bajo el root y rama `sn/`).

**Rollback de create**: flags locales `createdWorktree`, `createdBranch` y `createdJunctions[]`, que se activan solo despues de que el paso correspondiente termino bien. Si un paso falla, se deshacen solo los marcados, en orden inverso: unlink de junctions, `worktree remove --force` y `branch -D`. Una rama `sn/<slug>` preexistente se detecta antes (`rev-parse --verify --quiet`) y nunca se toca.

**Bordes**
- **Junctions**: se crean con `fs.promises.symlink(target, path, 'junction')`. Al borrar, para cada `linkedPaths` del manifiesto: `lstat`; si `isSymbolicLink()` (Node reporta asi los junctions en Windows), `fs.promises.unlink`. Nunca un `rm -r` sobre el junction. Si cualquier unlink falla, se aborta con `unlink_failed` antes de `git worktree remove`.
- **Bloqueos de Windows**: `git:worktreeRemove` recibe `paneId`. Main usa `PtyManager.ptyIdForPane(paneId)` + `kill(ptyId)` (`src/main/pty/PtyManager.ts:374`, `:291`) y espera el `onExit` de un sink temporal hasta 3s. Despues, `worktree remove --force` con 5 reintentos cada 400ms ante EBUSY/EPERM; si se agotan, `busy`. El renderer saca el pane del store solo despues de `ok` o si el usuario eligio Conservar.
- `inspect`: `git -C <path> status --porcelain=v2 -z` (cuenta), `git rev-list --count <base>..HEAD` y `git merge-base --is-ancestor <branch> <HEAD del repo>`.
- Rutas largas: `-c core.longpaths=true` solo en `worktree add`, sin tocar la config global.
- **Restaurar o reiniciar (FR-36)**: el renderer no puede ver el disco, asi que llama `worktreeInspect` antes de spawnear. Como defensa extra, `PtyManager.spawn` (hoy captura el fallo y emite `onExit(-1)`, linea 145) chequea `existsSync(cwd)` antes de `pty.spawn` y emite el error tipado `cwd_missing` en el evento de salida.
- La copia de `.env` saltea lo trackeado (`git ls-files --error-unmatch` exitoso), lo que no existe y cualquier ruta con `..` o absoluta.
- Panes con connection profile: no se ofrece worktree (FR-27), porque el agente trabaja en otro host.
- Capacidad: `gridForCount` (`src/renderer/components/layout/gridTemplates.ts:18`) no pasa de 12. Las entradas de worktree se deshabilitan con 12 panes.

## Requisitos no funcionales

- **Rendimiento**
  - status + `diff HEAD --numstat` de un repo de 5k archivos: p50 <= 150ms y p95 <= 400ms en esta PC.
  - Con 10 workspaces abiertos, git usa menos del 2% de CPU promedio en 10 minutos.
  - Nunca hay mas de 2 procesos git a la vez, con 1 slot reservado para el desktop.
  - El conteo de untracked lee como maximo 8MB por refresco y usa cache por mtime.
  - El panel abre la lista en menos de 300ms (desde cache) y un diff de 2000 lineas renderiza en menos de 100ms.
  - Watchers: 3 handles por commondir + 1 por target, con tope de 24 targets.
  - Ninguna operacion de git corre en el renderer ni bloquea el event loop de main.
  - Un alt-tab refresca como maximo los targets del workspace activo, mas 2 vencidos por tanda.
- **Seguridad**
  - Los paths de git y de abrir archivo se validan contra la lista vigente y contra el repoRoot.
  - Las operaciones destructivas de worktree se validan en main contra el manifiesto y contra `git worktree list`; solo se borran ramas `sn/` creadas por la app.
  - Flags anti-ejecucion: `core.fsmonitor=false`, `--no-ext-diff`, `--no-textconv`. Se limpian las variables `GIT_DIR` y similares del env.
  - `openPath` solo con lista blanca. El cwd y el repoRoot no salen hacia el celu.
  - `gitReq` con zod, limite de tasa y limite de pedidos en vuelo.
  - Sanitizacion C0/C1/ESC al pegar.
  - Las notas nunca se escriben en un pane plano.
  - Los drops con MIME interno necesitan nonce y presencia en la lista.
  - Las notas son locales y no se exportan con `config:export`.
- **Windows**
  - `git.exe` se resuelve por PATH con `windowsHide`.
  - Se usan junctions (sin admin) y `core.longpaths` solo en `worktree add`.
  - Reintentos ante EBUSY/EPERM y kill del pty desde main antes de borrar.
  - Las rutas se comparan sin distinguir mayusculas.
  - Root default bajo `dataDir()/worktrees` (autocontenido en el portable); `core.longpaths` en `worktree add` cubre las rutas que pasen MAX_PATH.
  - Ningun prompt de credenciales (`GIT_TERMINAL_PROMPT=0`, sin red).
  - `unsafe_repo` se informa sin modificar `safe.directory`.
- **Accesibilidad**
  - Los chips son `button` con `aria-label` completo ("Rama main, 5 archivos cambiados, 142 lineas agregadas, 37 eliminadas, 2 commits adelante").
  - La lista del panel se maneja con teclado (flechas, Enter, Esc) y el cambio de hunk se anuncia por `aria-live="polite"`.
  - El diff no depende solo del color: el gutter lleva `+`/`-`.
  - Los dialogos atrapan el foco y lo devuelven, y los panes deshabilitados del picker tienen `aria-disabled` con el motivo.
  - Se respeta `prefers-reduced-motion`.
- **i18n**
  - Todas las cadenas nuevas van en `src/renderer/i18n/en.ts` y `es.ts`, en las familias `git.*`, `changes.*`, `notes.*`, `worktree.*`, `race.*` y `drop.*`.
  - El formato de notas que se manda al agente queda fijo en ingles (`File:`, `Line:`, `User comment:`), porque es el contrato con el agente.
- **Estilo**
  - Color solo para estados (verde/rojo de conteos, rojo de conflictos y de borrar), segun el STYLEGUIDE del epic de pulido.
  - Los colores de diff salen de tokens del tema (`--color-ansi-green/red`), no de clases fijas.
  - Sin em dash ni en dash en UI ni en codigo.

## Riesgos y preguntas abiertas

| Riesgo o pregunta | Default recomendado |
|---|---|
| El rollback de `worktree add` podria borrar una rama preexistente del usuario. | Pre-chequeo `rev-parse --verify --quiet` y rollback solo de lo creado por la llamada (flags). Test obligatorio de rama intacta. |
| Borrar un junction podria seguir el link y borrar el `node_modules` original. | `lstat` + `unlink` explicito antes de `git worktree remove`; si falla, abortar. Test con centinela obligatorio. Junction apagado por defecto, con aviso de que `npm install` afecta a ambos. |
| Operaciones destructivas pedidas por un renderer comprometido o con bugs. | Main valida contra `worktrees.json` y `git worktree list`, solo ramas `sn/` y solo rutas bajo el root. El renderer manda `path` + `paneId`, nada mas. |
| Bloqueos de archivos en Windows al borrar el worktree (shell, editor, indexador). | Main mata el pty, espera la salida 3s y hace 5 reintentos cada 400ms. Despues, error con [Reintentar] y [Abrir carpeta]. Nunca borrar a medias sin avisar. |
| Texto de notas ejecutado en un shell. | Las notas solo van a panes con bracketed paste. Enter solo en panes de agente. Sanitizacion C0/C1/ESC. |
| `bracketedPasteMode` no alcanza para identificar un agente: bash por SSH/WSL lo activa, y PSReadLine tambien en algunas versiones (no lo verifique en esta PC). | "Formato agente" = tipo/provider de agente + bracketed. El resto de los panes con bracketed usa separador espacio. Los AC no asumen la version de PSReadLine. |
| MIME custom inyectado por otra app Chromium. | Nonce de sesion + path en la lista vigente + sin control chars. |
| Contencion de `index.lock` entre el poll y el git del agente. | `GIT_OPTIONAL_LOCKS=0` + single-flight + intervalo minimo. Si aparece `index.lock`, el refresco se saltea y se reintenta en el proximo tick. |
| Repos enormes o con untracked masivos (sin gitignore). | Tope de 5000 entradas con `truncated`, presupuesto de 8MB + cache por mtime para untracked, poll solo del workspace activo y paginas remotas de 48KB. |
| Ejecucion de comandos por config maliciosa del repo (fsmonitor, diff drivers). | `core.fsmonitor=false`, `--no-ext-diff`, `--no-textconv`. Sin hooks porque no se hace commit. |
| Celu revisando con el desktop en la bandeja: cache viejo. | `gitReq` con cache de mas de 2s fuerza refresco, target caliente 60s y reintento antes de `not_found`. |
| Diff paginado mezclando versiones. | Cache de 60s por `(key, path, staged)` con `diffRev` en cada pagina; si cambia, E3 reinicia en la pagina 0. |
| Worktrees de pane desde el celu: `gitReq` no lleva `paneId` y el snapshot no tiene un campo para la rama del worktree (Contratos compartidos). | El celu solo ve el target del workspace. Si hace falta, se propone agregar `paneId?` a `gitReq` y un campo de rama a `RemotePaneInfo` en Contratos compartidos antes de v3.0; este PRD no los usa. |
| Atajo del panel: podria chocar con otro epic (Quick Commands usa `Ctrl+Shift+Q`, paleta "Te esperan"). | `Ctrl+Shift+D` (hoy libre en `keymap.ts`), remapeable. El consolidado verifica que no se repita. |
| Donde viven las notas: en la config o en un archivo de main. | `review-notes.json` en `dataDir()` (main): no infla `config.json`, que se guarda entero en cada cambio. Las notas del celu viven en el celu (E3). |
| Concurrencia de notas entre desktop y varios celus. | No hay concurrencia: el celu no escribe en el store del desktop; sus notas viajan inline en `sendReviewNotes`. |
| Enter al mandar notas. | Apagado por defecto, con checkbox por envio y sin clave de config. Respeta la regla de no mandar Enter automatico. |
| Raiz de worktrees: junto al repo o fuera. | `dataDir()/worktrees/<repo>-<hash6>/` (configurable con `settings.worktreesRoot`): fuera del repo (los indexadores no ven worktrees anidados), autocontenido en el portable y sin ensuciar el Escritorio. `core.longpaths` en `worktree add` cubre rutas largas. |
| Que copiar al worktree. | `.env` y `.env.local`, solo si no estan trackeados, segun el checkbox `copyEnv` del dialogo (default tildado). Sobreescribible por `.snagentsos.json` del repo cuando exista. |
| `closePane` remoto o borrado de un workspace con worktrees. | Conservar siempre (no destructivo). Quedan en la lista de huerfanos (manifiesto + escaneo). |
| Workspaces y panes con connection profile (SSH). | Sin entradas de worktree. Chip con aviso "Repo local" en el tooltip. |
| Ahead/behind desactualizado sin fetch. | Sin fetch automatico. El tooltip dice "segun el ultimo fetch" y el watcher de `FETCH_HEAD` actualiza tras un fetch manual. |
| Cambios sin commitear en el checkout principal al crear un worktree. | Base `HEAD`, con aviso explicito en el dialogo. Ofrecer "stash y aplicar" queda fuera de alcance. |
| Chip con override de `pane.cwd` o `preset.defaultCwd` sin worktree. | El chip de workspace sigue a `workspace.cwd`. Esos panes no tienen chip propio; "Duplicar en worktree" si usa su cwd resuelto. |
| `confirmCloseRunning` solo cubre el cierre de la ventana con ptys vivos (`src/main/index.ts:229`); ningun cierre de pane pide confirmacion hoy. | El dialogo de worktree es la primera intercepcion de cierre por pane en `TilingGrid.tsx`. La confirmacion por pane generica no entra en esta epica (se le avisa al epic de pulido). |
| Carrera con Codex: la readiness es mas debil. | Timeout de 20s con envio y aviso. |
| Release de la carrera: la sintesis la agrupa con worktrees. | FR-33..35 en v3.0, como ultimo bloque y P2. Si v3.0 se atrasa, B y C pasan a una v3.1 explicita; nunca "v3.x". |
| Formato de notas: identico a Orca o con encabezado propio. | Identico a Orca (los agentes ya lo entienden y el contrato es estable), con header MIT en el archivo portado. |
| Hallazgo de revision descartado en parte: "node-pty falla al spawn antes de mostrar el aviso" con cwd inexistente. | No crashea: `PtyManager.spawn` ya captura el fallo y emite `onExit(-1)` (`PtyManager.ts:145`). Igual se adopta el chequeo previo con `worktreeInspect` (FR-36) y el error tipado `cwd_missing`, porque mejora la UX. |
