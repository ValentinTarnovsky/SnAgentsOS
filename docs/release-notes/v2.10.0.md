## What's new in 2.10.0

A console in bypass mode no longer sits all night on a permission prompt, and **Mark all read** clears the workspace badge again.

### Agents

- **Auto-yes to permissions**: a new setting in **Settings > Agents > Behavior** (off by default). SnAgentsOS then answers Claude Code permission prompts by itself, through the hooks integration. It covers the ones that still appear in bypass mode, like a dangerous `rm` or a request from one of the console's teammates shown in the lead console.
  - **Only consoles in bypass** answers only sessions running in `bypassPermissions`.
  - **Always** answers in any mode.
  - It never answers a question, a plan approval or a usage limit menu, and Claude Code deny rules still win.
  - An approved prompt shows no request and sends no notification. Each one adds a line to `logs/autoyes.log` with the console, the tool and the mode, never the command.
  - It needs the hooks integration (**Settings > Notifications**).

### Sidebar and phone

- **Mark all read works on everything the badge counts**: it used to clear only finished or failed consoles, so a badge that came from an open request or a `snaos needs` stayed on, and a muted console kept the item enabled while the click did nothing. Now the workspace badge goes to 0:
  - a finished or failed console is marked seen;
  - an open request stops asking for attention but stays open and answerable;
  - a `snaos needs` is cleared.
  A new event raises the badge again. **Mark as read** on a single console follows the same rule.
- On the phone, **Mark all read** and **Mark as read** do the same with a 2.10.0 desktop. With an older desktop they keep the old behavior.
